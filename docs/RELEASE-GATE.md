# Jump Agent v1.0 发布门禁

以下项目必须全部通过，v1.0 才可发布。

## 正向验收

- [ ] 安装 → 配置 Key → 首轮对话全程无注册或登录触点。
- [ ] 界面任何位置都不可见完整 API Key，并完成截图审计。
- [ ] `read/write/edit/grep/glob` 与 `bash` 在工作区内可用；越界读取走权限门，越界写入展示 diff 并等待批准。
- [ ] `.env`、`.ssh`、云凭据等高敏感路径每次读取均弹框，且不缓存授权。
- [ ] Craft、Plan、Ask 三档模式的行为契约用例全部通过。
- [ ] 多会话并行互不串扰；杀进程重开可恢复列表、历史和排队项，恢复队列不会自动发送。
- [ ] 长对话可自动压缩，压缩后上下文仍连贯。
- [ ] 会话中切换模型供应商后可无缝继续。
- [ ] 断网、错误 Key、工具异常均显示错误卡片，应用不崩溃、不白屏。
- [ ] 任一会话可由 JSONL 完整回放为时间线。
- [ ] `ask_user` 支持多步、选项、图片和推荐标记。
- [ ] 子任务派发后父会话不阻塞；完成事件能唤醒父会话并取得输出。
- [ ] 未参与开发的测试者能在干净机器上 10 分钟内完成安装并跑通核心链路。

## 负面验收

- [ ] 不主动登录任何外部服务。
- [ ] 不在未获批准时写入工作区外。
- [ ] 永不执行不可逆删除或覆写，任何授权都不可覆盖此规则。
- [ ] 不在对话中输出完整 Key 或长段密文。
- [ ] 不在未搜索去重时重复写入记忆。
- [ ] 不虚构未装配的能力；能力自述必须来自注册表。
- [ ] 不静默吞错或假装成功。
- [ ] 重启后不自动发送排队消息。

## 发布证据

每项验收应关联自动化测试、录屏、日志或测试报告。失败项必须有负责人和阻塞 Issue；口头确认不能替代证据。
